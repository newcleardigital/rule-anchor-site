DORA and AI-written code: what the change record has to show

DORA has applied since 17 January 2025. It does not mention AI coding agents. It does not need to: Article 9(4)(e) asks for ICT change management under which every change is recorded, tested, assessed, approved, implemented and verified in a controlled manner. A change an agent wrote is a change.

The five facts an auditor will ask for

  1. Which rule the change implements. The article, scheme rule or contract clause, quoted, not paraphrased.
  2. How that rule was read. The agreed interpretation, and who agreed it.
  3. What changed. The files and lines, at a commit you can check out again.
  4. How it was tested. A test that exists for that rule, and that passes.
  5. Who approved it, independently. RTS 2024/1774 Article 17(1)(b) asks for mechanisms that keep the functions approving a change independent of those requesting and implementing it.

Why AI changes make this harder

A human developer carries the context between pull requests. An AI agent starts each session from nothing: it re-reads the code, guesses what the rule meant, and may decide differently from last week. Three failures follow, and none of them shows up in a normal review:

  • A fixed value from the rulebook is typed into a second file. The next change moves one copy.
  • The agent's own reading of a rule becomes the rule, with nobody accountable for it.
  • The traceability table is rebuilt by hand before each audit, and is out of date the day after.

Where each fact should come from

FactSource that cannot drift
Rule and readingA catalogue in the repository: one numbered requirement per rule, pointing to its paragraph
What changedGit: the commit and the lines that cite the requirement ID
TestedA test named after the requirement ID, run in CI
ApprovedA separate commit by a named approver that changes only the catalogue
IndependentGit history: was the approver also an author of the code that implements the rule?

When all five come from the repository, the record is generated, not assembled. It can be produced for any commit, including last year's.

Questions

Does DORA forbid AI-written code?
No. It asks that every change, whoever or whatever wrote it, is recorded, tested, assessed and approved under your change-management procedure.
Is a pull-request approval enough?
It shows someone clicked approve. It does not show which rule the change implements, how the rule was read, or that the approver was independent of the people who changed the code.
