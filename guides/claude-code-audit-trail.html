An audit trail for Claude Code: rule, change, test and approver for every AI edit

Claude Code writes good code and keeps no record of why. Each session starts fresh, so the reason a value is 0.2 and not 0.3 lives only in the chat that is gone. Here is how to keep the trail in the repository instead.

The mechanism, step by step

  1. Session start → read the record. The session reads the rule catalogue, the decisions and the last handover note before writing anything, so session 12 cannot quietly contradict session 3.
  2. Every save → checked. A PostToolUse hook runs after each file the agent writes. A rulebook value typed into the logic, an unknown requirement ID or a banned word is sent back to the agent (exit code 2), and it fixes it in the same turn.
  3. Every build → the same checks. CI runs the exact scripts the hook used, plus: every rule has a test named after it, generated documents match their source, every file is either governed or exempt.
  4. Approval → a person, separately. The agent cannot sign a reading; a named approver does, in their own commit.
  5. Release → the record is exported. One command joins the catalogue, the code scan, the test scan and git history into a CSV and a printable page, stamped with the commit.

What you can do today, free

Two parts of this run without any purchase. Anchored Lite is a Claude Code plugin that does steps 1 to 3 for your own list of fixed values and words. Anchored Scan is a GitHub Action that comments on every pull request with fixed values copied across files and generated files edited by hand.

Questions

Does any code leave the repository?
No. The checks are plain Python scripts in your repository and your CI runner.
Does it slow the agent down?
Each check reads only the file just saved. A broken rule costs the agent one extra edit in the same turn.
