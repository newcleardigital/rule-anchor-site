Why AI coding agents copy fixed values, and how to catch it on every pull request

Ask an agent to add a fee to the quote endpoint and it will often write amount * 0.015, even though FEE_RATE = 0.015 already exists three folders away. It did not see it, and the number was right. Six months later the fee changes, one copy moves, and nobody notices until finance does.

Why it happens

  • The agent reads the files near its task, not the whole codebase.
  • A literal that matches the spec looks correct to the agent and to a reviewer.
  • Tests pass: both copies have the same value, today.

Catching it without configuration

Anchored Scan is a free GitHub Action. On every pull request it looks for numbers used in logic (beside a comparison, or multiplying or dividing) in two or more files outside tests and vendored code. Sizes, bit masks, HTTP status codes and small whole numbers are skipped. It posts one comment and updates it on each push:

| Value   | Files | Where                                    |
|---------|-------|------------------------------------------|
| 0.015   | 2     | api/quote.py:2 ✱, app/fees.py:3          |
| 5000    | 2     | api/quote.py:3 ✱, app/fees.py:2          |

It also flags a generated file edited by hand in the pull request: the edit is lost the next time the generator runs.

Stopping it before the pull request

With Anchored Lite in Claude Code, you list the values your product decides on purpose and the one file they live in. The moment the agent types one elsewhere, it is told where to read it from and fixes it in the same turn.

on: pull_request
permissions:
  contents: read
  pull-requests: write
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: newcleardigital/anchored-scan@v1

Questions

Will it fail my build?
Not without configuration: it only advises. Add anchor-core.json naming your watched values and it fails the build on a copy.
Does it send my code anywhere?
No. It runs in your runner and talks only to the GitHub API of your repository, to read the pull request's files and write its comment.
