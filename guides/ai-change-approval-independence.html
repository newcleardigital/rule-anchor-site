Who may approve a change an AI agent wrote? RTS 2024/1774 Article 17(1)(b)

Commission Delegated Regulation (EU) 2024/1774, Article 17(1)(b), asks financial entities to have mechanisms that ensure the independence of the functions that approve changes from the functions that request and implement them. An AI coding agent is an implementer. So is the developer who prompted it.

Three things that look like approval and are not

  • A flag in a file. Anyone, including the agent, can type "approved": true.
  • A merged pull request. It shows the merge, not which rule was approved or how it was read.
  • A name in a spreadsheet. It is not tied to the code version that shipped.

The mechanism that is

  1. The agent is blocked from approving. A hook that runs before every edit refuses any change that signs a reading or changes the approver list, and tells the agent who must approve.
  2. The approver signs in their own terminal. One commit, authored by them, that changes only the catalogue of rules.
  3. CI checks the history. A sign-off counts only if its commit is by an approver listed at that commit, names them, carries no AI co-author and changes no code.
  4. The record checks independence. For each rule, the authors of every commit to the code that implements it are compared with the approver. If they overlap, the record says so.

The result is a row per rule that an auditor can re-derive from the repository: who changed it, whether an AI agent helped, who approved it, in which commit, and whether that approver was independent.

Questions

Can the developer who prompted the agent approve?
Not under a reading of Article 17(1)(b) that treats the requester and implementer as one function. The record makes the overlap visible either way.
Is a git author email proof of identity?
It is self-declared. History proves who claimed to approve; branch protection with required code-owner review, or signed commits, proves it on the platform.
