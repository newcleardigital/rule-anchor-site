They give the AI the rules. We make it follow them.

Requirements tools now hand your specification to the AI as context. Context can be skipped. Anchored sits in the agent's working loop and in your build, so a broken rule is stopped before it goes any further.

  • The agent types a number from the specification into the code Stopped on that file. The agent is told which requirement the number belongs to and where to read it from. Stopped
  • The code cites a requirement that does not exist Stopped, with the unknown ID named. No code can claim to follow a rule nobody wrote. Stopped
  • A requirement nobody has approved yet The agent will not start building on it, and names the person who has to approve it. Waits for a person
  • A requirement without a passing test named after it The build fails. A comment that claims coverage is not evidence; a test is. Build fails

Four steps, one of them human.

We call the method Anchor-based development. The part of your code a specification governs, usually 15 to 25 percent, is anchored to it; everything else is built the way you build it today.

  1. Bring in your specification

    The agent drafts one numbered requirement per rule, each pointing to the paragraph it came from, all marked unapproved, with every unclear point listed.

  2. A person approves each one

    Your clinical or regulatory lead decides what each requirement means. Only the people you name can approve.

  3. Every change is checked

    As the agent writes, and again in your build. Each requirement needs its own passing test.

  4. Export the proof

    One command produces the traceability record for the current code version, ready for the audit.

What it does not do.

Your quality team and your notified body decide compliance. Anchored gives them evidence they can check.

It does not interpret your rules

If your expert approves a reading, the code follows that reading, and the record shows who approved it.

It does not make you compliant

It proves that the code does what the approved requirements say. It is not legal or regulatory advice.

It does not take your code anywhere

The checks are plain Python scripts that run in your repository and your build. Nothing is sent to us.

Questions.

We already use Jama, Polarion or Ketryx.

Keep them. They hold the requirements; Anchored works where the code is written and stops untraced changes before they exist. Its evidence exports as a CSV you can bring into those tools.

We don't use AI on certified code yet.

Then this is the easiest time to start: setup is simplest before the first AI-written line, and the record is complete from day one.

Is it only for medical devices?

No. It fits any software that must follow a written document: payment and banking rules, insurance tariffs, safety standards for cars, trains and aircraft, or a contract. Medical-device software is where we start.

What do we need?
