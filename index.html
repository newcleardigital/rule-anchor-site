The problem

AI writes your code faster than anyone can check it.

In regulated software (fintech, insurance, anything bound by a law, standard or contract), “the AI wrote it and it looks right” won’t pass an audit.

Teams must show that each rule from the outside authority became code, was tested, and was checked by a named person.

Today that proof sits in spreadsheets, Jira tickets and memory.

How it works

They give the AI the rules. We make it follow them.

A person signs each rule first. Anchored checks every change as the AI writes it, and again before release.

  1. Caught while the AI types

    When the agent saves a file, the check runs. A number from the rulebook typed into the code, a requirement ID that does not exist, a banned name: each is named with its file and line, and the agent fixes it in the same turn. Your build runs the same checks again, and a rule without a passing test fails it.

    Why AI agents copy fixed values
    CaughtLine 9: 0.2belongs to IF-CAP-001
    Approved byM. PetrovaHead of compliance

  2. The AI cannot approve itself

    A reading of a rule counts only when a named person signs it, in their own terminal, in a commit that changes nothing else. The agent is blocked from signing or rewording a signed rule, and CI checks every sign-off against the approver list. The record shows it when an approver also changed the code.

    Rule · approver · approval commit · AI-assisted change · approver independent of the implementers

  3. Proof for internal audit and the regulator

    One command exports the change record for the current commit: the rule and its article, the agreed reading, who approved it and in which commit, where it is implemented, who changed that code, whether an AI helped, whether the approver is independent, and the test that proves it. As CSV or a printable page.

Which rulebooks does it work with?

Any written document your software must follow: a product specification, a contract, pricing and consumer rules, or payment and billing rules.

What do we need?

For Anchored: Claude Code, a GitHub repository and Python 3 in your CI. The free Scan needs only GitHub. The checks work with TypeScript, Python, Java, Kotlin, C#, Go, Rust and more.

Does all our code have to change?

Only the part of your code a rulebook governs is anchored to it. You choose the folders; everything else is built the way you build it today.

How do the rules get in?

The agent drafts one numbered requirement per rule, each pointing to the paragraph it came from, all marked unapproved, with every unclear point listed. Your domain expert decides what each requirement means. Only the people you name can approve.

Does it interpret our rules?

No. If your expert approves a reading, the code follows that reading, and the record shows who approved it.

Does it give legal advice?

No. It proves that the code does what the approved requirements say. What a rule means is decided by your people.

Does our code leave our servers?

No. The checks run in your repository and your build. Nothing is sent to us.
